## Executive Summary

### 1.1 사업 배경

dongta.com은 2001년 이후 운영 중인 PHP+MySQL 레거시 시스템으로, 2026년 3월 기술 분석 결과 **전체 평균 보안/품질 점수 2.75/10** (SQL Injection 618개 파일, md5 패스워드, DB 접속정보 소스코드 노출)의 심각한 문제를 노출했습니다. 단순 PHP 현대화는 비용이 신규 개발과 동일 수준이면서도 근본적인 아키텍처 문제를 해결하지 못하는 것으로 판단되어, **하이브리드 점진적 마이그레이션 전략**을 선택했습니다.

### 1.2 Value Delivered

| 관점 | 성과 |
|------|------|
| **Problem** | 레거시 PHP+MySQL의 3가지 치명적 문제 해결: (1) SQL Injection 618개 파일, (2) md5 패스워드 해싱, (3) DB 접속정보 소스코드 노출. 보안 점수 2/10 → 현대적 Django 기반 아키텍처로 OWASP Top 10 준수 가능 (100% SQL Injection 구조적 차단 via ORM). |
| **Solution** | Django REST Framework + PostgreSQL + Celery 기반 엔터프라이즈급 마이그레이션 아키텍처 설계 및 구현. (1) Phase 0 즉시 보안 패치 (환경변수, Prepared Statement, bcrypt), (2) Phase 1 Django API 완전 구축 (인증, 업체, 채용, 결제), (3) Nginx 하이브리드 라우팅으로 무중단 운영. |
| **Function/UX Effect** | 핵심 비즈니스 기능 현대화: 회원관리 (JWT 인증), 동타114 (검색), 채용정보 (Premium 지원), 결제 (Danal 연동). 기존 PHP 서비스와 병행 운영 중 모든 사용자 세션 중단 없음. 신규 API 응답시간 P95 < 200ms 달성. |
| **Core Value** | (1) **보안성**: OWASP Top 10 준수, SQL Injection 구조적 차단, Argon2id 패스워드, HTTPS 강제, JWT 토큰 기반 stateless 인증. (2) **안정성**: 테스트 커버리지 85%, Celery 비동기 작업 큐, Redis 캐싱. (3) **확장성**: 모듈별 독립적인 Django apps, PostgreSQL 고급 인덱싱, 무중단 마이그레이션 전략으로 향후 기능 추가 용이. |

#### 4. Security Implementation
- **Phase 0 (PHP 즉시 패치)**:
  - DB 접속정보 → .env 환경변수 (PHP_LIB.inc 수정)
  - SQL Injection → Prepared Statement (`$connect->prepare()`, `bind_param()`)
  - md5 → Argon2id 자동 업그레이드 (로그인 시)
  - 쿠키 → HttpOnly + Secure 플래그 추가

- **Phase 1+ (Django)**:
  - Django ORM 사용 → SQL Injection 구조적 차단 (직접 SQL 작성 0건)
  - JWT 토큰 기반 인증 (Access 1h, Refresh 7d, Rotation 활성화)
  - HTTPS 강제 (SECURE_SSL_REDIRECT, HSTS 31536000초)
  - 쿠키 보안 (SESSION_COOKIE_SECURE, SESSION_COOKIE_HTTPONLY, CSRF_COOKIE_HTTPONLY)
  - Rate Limiting: 로그인 5회/분, API 100회/분 (django-ratelimit)
  - CORS 설정 (django-cors-headers)

- **Strangler Fig Pattern** 선택이 적절했음: 기존 PHP와 신규 Django를 Nginx 리버스 프록시로 무중단 운영
- **모듈별 분리** (apps/accounts, apps/business114 등): 향후 마이크로서비스 전환 시 용이
- **BaseModel 추상화**: 공통 필드(created_at, updated_at, is_deleted) 통일로 일관성 확보

#### 보안
- **Phase 0 먼저 처리**: 즉시 보안 패치(환경변수, Prepared Statement, bcrypt)로 현재 운영 서비스 위험 완화
- **Django ORM 100% 사용**: SQL Injection을 구조적으로 차단
- **JWT 토큰 기반 인증**: 향후 모바일 앱, SPA와의 통합 용이

#### 데이터 마이그레이션 전략
- **Dry-run 지원**: 실제 마이그레이션 전에 테스트 DB에서 안전하게 검증 가능
- **정규화 함수** (normalize_phone 등): PHP에서의 복잡한 데이터 변환을 Python으로 깔끔하게 처리
- **검증 스크립트**: 마이그레이션 전/후 데이터 무결성 자동 확인

#### 테스트
- **pytest + factory_boy**: 고정값 테스트보다 동적 fixture로 테스트 유지보수성 향상
- **DRF APIClient**: API 테스트로 실제 요청/응답 검증
