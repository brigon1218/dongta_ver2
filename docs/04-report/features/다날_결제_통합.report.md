## 1. Overview

### 1.1 Purpose

보안 취약점이 존재하던 PHP 레거시 다날 결제 로직을 현대적인 Django API로 이전하고, 하이브리드 운영 기간 동안 데이터 정합성을 유지하기 위해 신규 DB(PostgreSQL)와 레거시 DB(MySQL)에 동시에 결제 내역을 기록하는 체계를 구축함.

### 1.2 Accomplishments

- **SDK 현대화**: 다날 CPAY 규격을 준수하는 Python 전용 클라이언트(`DanalClient`) 구현 (EUC-KR 지원)
- **무중단 이관**: 결제 성공 시 Celery를 통해 비동기로 레거시 MySQL(`DongtaPointCharge`)에 실시간 동기화 구현
- **보안 강화**: SQL Injection 위험이 있는 직접 쿼리 제거 및 환경변수를 이용한 API Key 관리 적용
- **기능 완비**: 결제 준비(Ready), 승인(Approve), 취소(Cancel)의 전체 라이프사이클 API 구현 완료

## 2. Implementation Details

### 2.1 Core Features

| Feature | Description | File Path |
|---------|-------------|-----------|
| **Danal SDK Wrapper** | 다날 API 통신, EUC-KR 인코딩 및 응답 파싱 | `apps/payment/danal/client.py` |
| **결제 준비/승인 API** | 결제 세션 초기화 및 최종 승인 처리 | `apps/payment/views.py` |
| **이중 기록(Sync)** | Celery 비동기 MySQL 데이터 기록 및 재시도 로직 | `apps/payment/tasks.py` |
| **모델 확장** | TID, 결제상태, 동기화 여부 등 관리 필드 추가 | `apps/payment/models.py` |

### 2.2 Key Technologies

- **Python SDK**: `requests` 기반 커스텀 래퍼 구현
- **Async Task**: `Celery` + `Redis`를 이용한 비동기 DB 동기화
- **Database**: `PostgreSQL` (Primary), `MySQL` (Secondary/Legacy)
- **Security**: `pycryptodome` (향후 HMAC 서명 확장 대비), Django ORM
