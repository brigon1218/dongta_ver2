## 5. 의도적 적응 사항 (Design → Implementation)

### 1. `board.Post` 액션: hide_posts → delete_posts
- **설계**: `is_hidden=True` 처리
- **현실**: Post 모델에 `is_hidden` 필드 없음
- **적응**: `queryset.delete()` 사용
- **정당성**: ✅ 설계 의도(게시글 제거)는 동일하게 달성

### 2. `monitoring` 모델: EventSource → EventOutbox
- **설계**: `EventSource` 모델 Admin 등록
- **현실**: `EventSource`는 TextChoices (모델이 아님)
- **적응**: `EventOutbox` 모델 등록 (실제 이벤트 추적용)
- **정당성**: ✅ 의도(이벤트 모니터링)는 더 정확하게 구현

### 3. `monitoring` 컬럼명: source_type → event_type
- **설계**: `['id', 'source_type', 'status', 'created_at']`
- **현실**: EventOutbox 모델의 실제 필드명 확인
- **적응**: `['id', 'event_type', 'source', 'status', 'retry_count', 'created_at']`
- **정당성**: ✅ 실제 모델 필드를 정확히 반영

**결론**: 3개 적응 모두 "설계 의도 유지 + 실제 코드 구조 반영" ✅
