## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 운영 중인 동타 플랫폼의 시스템 상태, 사용자/사업장 통계, 결제 내역, 게시판 현황을 한눈에 파악할 관리 화면이 없어 운영 효율이 낮음. |
| **Solution** | Django Admin을 확장하여 커스텀 통계 대시보드 페이지를 추가. 기존 monitoring API를 재활용하고 각 앱의 모델을 Admin에 등록하여 통합 관리 화면 구현. |
| **Function UX Effect** | `/admin/` 접속 시 통계 요약 카드(사용자 수, 결제 합계, 게시글 수, 시스템 상태) 확인. 각 항목 클릭 시 상세 관리 페이지로 이동. |
| **Core Value** | 관리자가 별도 툴 없이 Django Admin에서 플랫폼 전체 현황을 즉시 파악하고 주요 데이터를 직접 관리할 수 있음. |

## 1. 요구사항

### 1.1 기능 요구사항

#### FR-01: 통계 대시보드 홈
- Django Admin 홈(`/admin/`)에 통계 요약 카드 4개 표시
- 수동 새로고침 방식 (페이지 로드 시 데이터 갱신)

**카드 구성:**
| 카드 | 데이터 소스 | 표시 내용 |
|------|------------|-----------|
| 시스템 상태 | `GET /api/v1/monitoring/status/` | DB/Redis/Celery 상태 |
| 사용자/사업장 | DB 직접 조회 | 전체 회원 수, 사업장 수, 오늘 가입 수 |
| 결제 현황 | DB 직접 조회 | 오늘 결제 건수, 총 결제 금액 |
| 게시판 현황 | DB 직접 조회 | 전체 게시글 수, 오늘 등록 수, 신고 건수 |

#### FR-02: 시스템 상태 모니터링
- 기존 `monitoring` 앱 API 활용
- Admin에서 `SystemStatusView` 데이터 시각적으로 표시
- 이벤트 목록 및 재처리 버튼 Admin 액션으로 연결

#### FR-03: 사용자/사업장 통계
- `accounts.Member` 모델 Admin 등록 (검색, 필터, 목록)
- `business114.BusinessInfo` 모델 Admin 등록
- 가입일 기준 필터, 상태별 필터 지원

#### FR-04: 결제 내역 관리
- `payment.PointAccount`, `payment.Transaction` (또는 관련 모델) Admin 등록
- 결제 상태별 필터, 날짜 범위 필터
- 환불 처리용 Admin 액션 (status 변경)

#### FR-05: 게시판/콘텐츠 관리
- `board.Post` 모델 Admin 등록
- 신고 게시글 필터, 카테고리별 필터
- 게시글 숨김/삭제 Admin 액션

### 1.2 비기능 요구사항
- Django Admin 기본 로그인 (`/admin/`, is_staff=True)
- 통계 카드 로드 3초 이내
- 모바일 대응 불필요 (관리자 PC 사용)
