## 1. Overview

### 1.1 Purpose

Phase 3까지 완료된 각 모듈 API들을 실제 운영 서버에서 안정적으로 서비스할 수 있도록 기술적 완성도를 높이고, 배포 프로세스를 자동화하여 휴먼 에러를 방지한다.

### 1.2 Background

- **현황**: 주요 도메인(`recruit`, `business114`, `board`, `mypage`)의 API 개발 및 동기화 파이프라인 구축 완료.
- **문제점**:
  - 대량 데이터 조회 시 JSONField 검색 성능 검증 필요.
  - 실제 운영 환경(AWS 등)에서의 배포 자동화 및 모니터링 체계 미흡.
- **목표**: 서비스 무중단 배포 기반 확보 및 성능 병목 제거.

---

## 2. Scope

### 2.1 In Scope

- **성능 고도화 (Optimization)**:
  - PostgreSQL GIN Index 적용 (취급품목, 직종 등 JSONField 검색용)
  - Redis 기반 API 캐싱 적용 (자주 변하지 않는 목록 조회)
  - DB Connection Pool 설정 최적화
- **운영 환경 구축 (Deployment)**:
  - Nginx, Gunicorn 상세 설정 튜닝
  - Docker Compose 운영용 프로파일 작성
  - CI/CD 파이프라인 (GitHub Actions) 기초 구축
- **보안 및 모니터링 (Hardening)**:
  - Sentry 연동을 통한 실시간 에러 로깅
  - API 처리 속도 및 트래픽 모니터링 (Prometheus/Grafana 고려)
  - Rate Limiting (django-ratelimit) 전역 적용 상태 점검

### 2.2 Out of Scope

- 클라우드 인프라(AWS) 신규 인스턴스 구축 (기존 서버 활용 전제)
- DB 클러스터링 및 읽기/쓰기 분리 (향후 트래픽 증가 시 고려)

### 3.1 Functional Requirements

|----|-------------|----------|--------|
| FR-01 | JSONField 전용 GIN 인덱스 생성 | High | Pending |

- **보안**: 운영 환경 비밀키 관리 (Secrets Manager 또는 GitHub Secrets).
- **복구**: 배포 실패 시 이전 버전으로 즉시 롤백 가능한 구조 확보.

## 4. Architecture

### 4.1 배포 파이프라인 Flow

1. **Code Push**: `main` 브랜치 병합
2. **CI**: Tests 실행, Lint 체크, Docker Image 빌드
3. **Registry**: 빌드된 이미지를 Container Registry에 업로드
4. **CD**: 운영 서버 접속 -> `docker-compose pull` -> 컨테이너 순차 재시작 (Rolling Update)

---

## 5. Implementation Roadmap

1. **Step 1**: PostgreSQL 인덱스 최적화 및 DB 마이그레이션 최종 점검
2. **Step 2**: 운영 서버용 Nginx/Gunicorn/Docker 설정 파일 튜닝
3. **Step 3**: 로깅(Sentry) 및 전역 보안 정책(Rate Limit) 적용
4. **Step 4**: GitHub Actions CI/CD 스크립트 작성 및 테스트
5. **Step 5**: 실제 운영 배포 및 E2E 테스트

---

## 6. Success Criteria

- 대량 데이터 검색 API 응답 속도 200ms 이하 유지
- 배포 자동화 스크립트 실행 시 원클릭 배포 성공
- 운영 서버 에러 발생 시 실시간 알림(Sentry) 수신 확인
- 일치율(Match Rate) 90% 이상 달성
