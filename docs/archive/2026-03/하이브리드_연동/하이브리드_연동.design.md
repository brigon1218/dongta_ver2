## 1. Overview

### 1.1 Design Goals

1. **무중단 하이브리드 운영**: Nginx로 요청 분기 (API → Django, 나머지 → PHP)
2. **데이터 정합성**: MySQL ↔ PostgreSQL 실시간 동기화
3. **높은 가용성**: 99.9% SLA 달성
4. **운영 용이성**: 자동 장애 복구, 모니터링 통합

### 1.2 Design Principles

- **역할 분담**: Nginx는 라우팅만, 비즈니스 로직은 각 서버에서 처리
- **이벤트 기반**: MySQL 트리거 → Redis 큐 → Celery 워커
- **재시도 가능**: 실패한 작업은 자동 재시도, 수동 개입 최소화
- **관찰 가능성**: 모든 동기화 이벤트 로깅 및 메트릭 수집
- **단계적 전환**: 모듈별로 Django로 완전 전환 가능하도록 설계

## 3. Data Synchronization Architecture

### 3.1 동기화 전략

#### 3.1.1 동기화 방향

```
이벤트 발생처:        동기화 방향:         대상:

PHP 로그인          →  회원 정보        →  PostgreSQL
PHP 업체 등록       ←  업체 정보        ←  (조회만, 역방향 불필요)
PHP 채용정보 등록   ←  채용 정보        ←  (조회만, 역방향 불필요)
PHP 결제            →  결제 이력        →  PostgreSQL + MySQL (이중 기록)
Django 회원 수정    →  회원 정보        →  MySQL (기존 사용자 영향 최소화)
```

#### 3.1.2 동기화 패턴

**패턴 1: MySQL 트리거 + Celery (비동기)**
```
MySQL Update Event
    ↓
MySQL Trigger (INSERT INTO event_log)
    ↓
Event Log Table (TBL_EVENT_LOG)
    ↓
Celery Task (Periodic)
    ↓
Read from event_log → PostgreSQL
    ↓
Mark as processed
```

**패턴 2: Outbox Pattern (트랜잭션 안전성)**
```
PHP: INSERT INTO MySQL (비즈니스 데이터)
     + INSERT INTO TBL_EVENT_OUTBOX (이벤트)  [같은 트랜잭션]
     ↓
Celery Polling: SELECT * FROM TBL_EVENT_OUTBOX WHERE processed=0
     ↓
PostgreSQL: INSERT (이벤트 적용)
     ↓
MySQL: UPDATE TBL_EVENT_OUTBOX SET processed=1
```

### 3.4 Celery Task 설계

#### 3.4.1 회원 정보 동기화 Task

```python
# apps/sync/tasks.py

from celery import shared_task
from django.db import transaction
import json
import logging

logger = logging.getLogger(__name__)

@shared_task(bind=True, max_retries=3, queue='sync')
def sync_member_data(self, event_id: int):
    """
    MySQL TBL_MEMB → PostgreSQL accounts.Member 동기화

    Args:
        event_id: TBL_EVENT_OUTBOX의 event_id

    Raises:
        Exception: 데이터베이스 에러 시 자동 재시도
    """
    from apps.sync.models import EventOutbox
    from apps.accounts.models import Member
    from django.db.utils import IntegrityError

    try:
        # 이벤트 조회
        event = EventOutbox.objects.get(event_id=event_id)
        payload = json.loads(event.payload)

        logger.info(f"[SYNC] Processing event {event_id}: {event.event_type}")

        with transaction.atomic():
            # 회원 정보 업데이트
            member, created = Member.objects.update_or_create(
                no_memb=payload['no_memb'],
                defaults={
                    'id_member': payload['id_member'],
                    'nm_member': payload['nm_member'],
                    'email': payload['email'],
                    'phone': payload['phone'],
                }
            )

            # 이벤트 마크
            event.processed = True
            event.processed_at = timezone.now()
            event.save()

        logger.info(f"[SYNC] Successfully synced member {payload['no_memb']}")
        return {'status': 'success', 'member_id': member.id}

    except EventOutbox.DoesNotExist:
        logger.error(f"[SYNC] Event {event_id} not found")
        return {'status': 'error', 'reason': 'event_not_found'}

    except IntegrityError as e:
        logger.error(f"[SYNC] Integrity error for event {event_id}: {e}")
        return {'status': 'error', 'reason': 'integrity_error'}

    except Exception as e:
        logger.error(f"[SYNC] Failed to sync event {event_id}: {e}")

        # 재시도
        if self.request.retries < self.max_retries:
            raise self.retry(exc=e, countdown=60 * (self.request.retries + 1))
        else:
            # 최대 재시도 초과
            event = EventOutbox.objects.get(event_id=event_id)
            event.error_message = str(e)
            event.save()
            logger.error(f"[SYNC] Giving up on event {event_id} after {self.max_retries} retries")
            return {'status': 'failed', 'reason': 'max_retries_exceeded'}
```

#### 3.4.2 데이터 정합성 검증 Task

```python
@shared_task(queue='default')
def verify_data_consistency():
    """
    MySQL ↔ PostgreSQL 데이터 정합성 검증
    불일치 발견 시 Slack 알림
    """
    from apps.accounts.models import Member
    from django.db import connection

    # MySQL 회원 수
    with connection.cursor() as cursor:
        cursor.execute("SELECT COUNT(*) as count FROM TBL_MEMB WHERE DL_GB = 'N'")
        mysql_count = cursor.fetchone()[0]

    # PostgreSQL 회원 수
    postgres_count = Member.objects.filter(is_deleted=False).count()

    # 검증
    discrepancy = abs(mysql_count - postgres_count)

    logger.info(f"[VERIFY] MySQL: {mysql_count}, PostgreSQL: {postgres_count}, Diff: {discrepancy}")

    if discrepancy > 10:  # 10건 이상 차이 시 알림
        send_slack_notification(
            channel='#alerts',
            message=f"⚠️ 데이터 정합성 문제: MySQL {mysql_count} vs PostgreSQL {postgres_count}"
        )

    return {
        'mysql_count': mysql_count,
        'postgres_count': postgres_count,
        'discrepancy': discrepancy,
        'status': 'ok' if discrepancy <= 10 else 'warning'
    }
```

## 6. 배포 및 롤백 전략

### 6.1 Blue-Green 배포

```
Blue (현재 운영)
    ↓
구성 확인 ← Green (새 버전)
    │
    ├─► Health Check 통과?
    │   YES ─► Traffic 전환 (Nginx weight 변경)
    │   NO  ─► 롤백
    │
    └─► Green이 새로운 Blue
```

```bash

# 2. 데이터베이스 마이그레이션 롤백
python manage.py migrate <app> <migration-number>

# 3. Gunicorn 재시작
sudo systemctl restart dongta-django

# 4. Nginx 트래픽 복원
# weight 조정 또는 upstream 변경
```
