## 3. Gap Analysis (Design vs Implementation)

### 3.1 API Endpoints

| Design | Implementation | Status | Notes |
|--------|---------------|:------:|-------|
| GET `/api/v1/mypage/profile/` | `ProfileView.get()` | ✅ | `RetrieveUpdateAPIView` 상속 |
| PATCH `/api/v1/mypage/profile/` | `ProfileView.patch()` | ✅ | partial=True 적용 |
| POST `/api/v1/mypage/password/` | `PasswordChangeView.post()` | ✅ | old_password 검증 포함 |
| POST `/api/v1/mypage/withdraw/` | `WithdrawalView.post()` | ✅ | soft_delete + is_active=False |
| GET `/api/v1/mypage/points/` | `PointHistoryView.list()` | ✅ | balance + history 반환 |
| GET `/api/v1/mypage/summary/` | `ActivitySummaryView.get()` | ✅ | 4개 앱 카운트 집계 |

URL 라우팅: `config/urls.py:17` 및 `apps/mypage/urls.py` 정상 등록 확인.

**API Match Rate: 6/6 = 100%**

### 3.2 Business Logic

#### 🔵 Changed: ActivitySummary 응답 형식 불일치

| Item | Design (Section 3.2) | Implementation (views.py:127-134) | Impact |
|------|-----|--------|--------|
| 응답 구조 | `{ "counts": { "posts": N, ... } }` | `{ "posts_count": N, ... }` | Medium |
| 키 네이밍 | `posts`, `comments`, `businesses`, `job_notices` | `posts_count`, `comments_count`, `businesses_count`, `job_notices_count` | Medium |

Design은 `counts` 객체로 감싸는 구조를 명시하나, 구현은 플랫 구조에 `_count` 접미사를 사용.

#### 🔴 Missing: want_quit 필드 미설정

| Item | Design Location | Description |
|------|-----------------|-------------|
| want_quit 설정 | Design 3.3 (탈퇴 로직) | `WithdrawalView`에서 `want_quit=True` 미설정 |

`Member.want_quit` 필드가 모델에 존재하며(`models.py:58`), MySQL 동기화(`sync/tasks.py:116`)에서 사용되나 탈퇴 처리 시 업데이트되지 않음.

#### 🔵 Changed: 탈퇴 로직 실행 순서

| Step | Design (Section 3.3) | Implementation (views.py:77-82) |
|------|-----|--------|
| 1 | 비밀번호 검증 | 비밀번호 검증 ✅ |
| 2 | is_active = False | soft_delete() 호출 |
| 3 | soft_delete() 호출 | is_active = False + quit_reason 저장 |
| 4 | 탈퇴 일시/사유 저장 | (위와 통합) |

`transaction.atomic()` 내에서 수행되므로 기능적으로 동등. **Impact: Low**

#### ⚠️ 포인트 사용 내역 미포함

Design Section 3.1은 "충전/사용 내역 포함"을 명시하나, 구현은 `PaymentHistory`(충전)만 조회. Design 자체에서 "초기 버전은 PaymentHistory 목록 제공, PointLog 추후 검토"라고 기술하므로 **의도된 제한**.

`PasswordChangeView`가 두 곳에 존재:
- `apps/accounts/views.py:107-117` → `POST /api/v1/auth/password/change/`

동일한 기능이 다른 URL에서 중복 제공됨. 향후 하나로 통합하거나 Design에 명시 필요.
