## 1. Overview

### 1.1 Purpose

현재 운영 중인 dongta.com PHP+MySQL 시스템의 치명적 보안 취약점(SQL Injection, md5 암호화, XSS)과 높은 기술 부채(216,458줄 절차형 코드)를 해결하고, 현대적인 Python/Django+PostgreSQL 아키텍처로 전환하여 서비스의 안정성, 보안성, 확장성을 확보한다.

### 1.2 Background

**현황 분석 결과 (2026-03-02)**:
- PHP+phtml 파일: 651개 / 총 코드: 216,458줄
- 보안 점수: **2/10** (SQL Injection 618개 파일, md5 암호화, DB비밀번호 소스코드 노출)
- 코드품질 점수: **3/10** (레거시 함수 854건, ereg() PHP 7.0 제거됨)
- 아키텍처 점수: **4/10** (데스크톱은 절차형, 모바일만 CodeIgniter MVC)
- 테스트 점수: **1/10** (테스트 코드 전무)
- **전체 평균: 2.75/10**

**결론**: 단순 최적화(PHP 현대화)는 비용이 신규 개발보다 높고 근본 문제를 해결하지 못함. 하이브리드 점진적 마이그레이션이 최적 전략.

### 1.3 Related Documents

- 기술 분석 보고서: 현 세션 탐색 에이전트 결과 (2026-03-02)
- 참고 아키텍처: Django REST Framework, PostgreSQL

## 5. Risks and Mitigation

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| 결제 시스템(Danal) 마이그레이션 중 장애 | High | Medium | 결제는 최후 단계로 이동, PHP 결제 병행 운영 기간 연장 |
| 기존 PHP 코드 분석 누락으로 기능 손실 | High | Medium | 모듈별 E2E 테스트 스크립트 작성 후 전환 |
| MySQL → PostgreSQL 데이터 손실/불일치 | High | Low | 마이그레이션 스크립트 + 검증 쿼리 작성, 롤백 계획 수립 |
| 하이브리드 기간 데이터 동기화 지연 | Medium | Medium | 이벤트 큐(Celery+Redis) 도입으로 실시간 동기화 |
| Django 학습 곡선 (팀 역량) | Medium | Medium | 초기 2주 Django 트레이닝, 페어 코딩 진행 |
| PHP ereg() 등 레거시 함수 동작 차이 | Low | High | Phase 0에서 preg_match 교체 완료 후 Phase 1 진행 |
| 서비스 중단 없는 전환 실패 | High | Low | 블루/그린 배포 전략, DB 동기화 스크립트 사전 검증 |

## 6. Architecture Considerations

### 6.1 Project Level Selection

| Level | Characteristics | Selected |
|-------|-----------------|:--------:|
| **Starter** | Simple structure | ☐ |
| **Dynamic** | Feature-based modules, BaaS integration | ☐ |
| **Enterprise** | Strict layer separation, microservices | ✅ |

> **Enterprise** 선택 이유: 운영 중인 서비스의 무중단 마이그레이션, 복잡한 비즈니스 도메인(114, 채용, 결제), 하이브리드 운영 기간 필요

### 6.2 Key Architectural Decisions

| Decision | Options | Selected | Rationale |
|----------|---------|----------|-----------|
| Backend Framework | Django / FastAPI / Flask | **Django** | Admin 자동생성, ORM, DRF 생태계 |
| API Style | REST / GraphQL | **REST (DRF)** | 기존 PHP 구조와 호환성 높음 |
| Database | PostgreSQL / MySQL | **PostgreSQL** | JSONB, 고급 인덱싱, 안정성 |
| Auth | JWT / Session / OAuth | **JWT (SimpleJWT)** | SPA/모바일 지원, stateless |
| Task Queue | Celery+Redis / RQ | **Celery+Redis** | 데이터 동기화, 이메일 발송 |
| Container | Docker + Docker Compose | **Docker** | 환경 일관성, CI/CD |
| Deployment | AWS ECS / EC2 / Kubernetes | **AWS ECS** | 현재 RDS AWS 사용 중 |
| Frontend (향후) | Next.js / Vue.js | **Next.js** | React 기반, SSR 지원 |

### 6.3 Architecture Overview

```
[현재 상태] PHP+MySQL (레거시)
┌─────────────────────────────────────────┐
│  Apache + PHP                           │
│  ├── /include (절차형 공통)              │
│  ├── /admin (절차형 스크립트)           │
│  ├── /m (CodeIgniter MVC)               │
│  └── /recruit, /114, /mypage 등         │
│                                         │
│  MySQL (AWS RDS)                        │
└─────────────────────────────────────────┘

[하이브리드 기간] PHP + Django API 병행
┌─────────────────────────────────────────┐
│  Nginx (Reverse Proxy)                  │
│  ├── /api/* → Django REST API           │
│  └── /* → 기존 PHP (Apache)             │
│                                         │
│  Django (DRF)         PHP (레거시)      │
│  ├── /api/auth/       ├── /login.phtml  │
│  ├── /api/members/    ├── /member/      │
│  ├── /api/114/        ├── /114/         │
│  └── /api/recruit/    └── /recruit/     │
│                                         │
│  PostgreSQL (신규) ↔ MySQL (기존, 동기화) │
└─────────────────────────────────────────┘

[최종 상태] Django+PostgreSQL (완전 전환)
┌─────────────────────────────────────────┐
│  Django REST API + Next.js Frontend     │
│  PostgreSQL (AWS RDS)                   │
│  Redis (캐싱 + Celery)                  │
│  S3 (파일 업로드)                        │
└─────────────────────────────────────────┘
```
