## 1. Design Goals

1. **RESTful API**: 표준 HTTP 메소드를 사용하여 기업 및 구직자 서비스를 명확히 구분
2. **Object-level Permissions**: 본인이 작성한 데이터만 수정/삭제 가능하도록 보안 강화
3. **Flexible Search**: 다중 직종(JSONField) 및 지역 필터링을 지원하는 고도화된 검색 기능
4. **Service Layer**: 포인트 차감 및 프리미엄 기간 설정 로직을 서비스 레이어로 분리하여 응집도 향상

## 2. API Specification

### 2.1 기업용 서비스 (Company & JobNotice)

| Method | Path | Description | Permission |
|--------|------|-------------|------------|
| GET | `/api/v1/recruit/companies/` | 내 회사 목록 조회 | IsAuthenticated |
| POST | `/api/v1/recruit/companies/` | 회사 정보 등록 | IsAuthenticated |
| PATCH | `/api/v1/recruit/companies/:id/` | 회사 정보 수정 | IsOwner |
| GET | `/api/v1/recruit/notices/` | 채용 공고 목록 (필터 검색) | AllowAny |
| POST | `/api/v1/recruit/notices/` | 채용 공고 등록 | IsAuthenticated |
| GET | `/api/v1/recruit/notices/:id/` | 채용 공고 상세 | AllowAny |
| PATCH | `/api/v1/recruit/notices/:id/` | 채용 공고 수정 | IsOwner |
| DELETE | `/api/v1/recruit/notices/:id/` | 채용 공고 삭제 | IsOwner |
| POST | `/api/v1/recruit/notices/:id/premium/` | 프리미엄 공고 신청 | IsOwner |

### 2.2 개인용 서비스 (JobSeeker)

| Method | Path | Description | Permission |
|--------|------|-------------|------------|
| GET | `/api/v1/recruit/seekers/` | 내 구직자 프로필 조회 | IsAuthenticated |
| POST | `/api/v1/recruit/seekers/` | 구직자 프로필/이력서 등록 | IsAuthenticated |
| PATCH | `/api/v1/recruit/seekers/:id/` | 이력서 수정 | IsOwner |

## 3. Core Logic Design

### 3.1 프리미엄 공고 전환 로직 (Point Integration)

프리미엄 신청 시 다음 절차를 따릅니다:
1. **잔액 확인**: 사용자의 `PointAccount`에서 신청 비용(예: 10,000P) 확인
2. **포인트 차감**: `total_used` 업데이트 및 기록
3. **기간 설정**: `JobNotice`의 `is_premium=True`, `premium_start_date=Today`, `premium_end_date=Today+30days` 설정
4. **트랜잭션**: 모든 과정은 `atomic`하게 처리

### 3.2 다중 필터 검색 (Search Filter)

- **직종 검색**: `occupations` (JSONField) 내에 특정 키워드가 포함되어 있는지 `contains` 연산자 사용
- **지역 검색**: `Member` 모델의 `region` 또는 `Company`의 `address` 기반 필터링
- **정렬**: 프리미엄 공고 우선 노출 후 최신순 정렬

## 4. Component Structure

### 4.1 Serializers
- `CompanySerializer`: 회사 정보 정규화
- `JobNoticeSerializer`: 공고 정보 및 관련 회사 정보 중첩(Nested) 표현
- `JobSeekerSerializer`: 개인 프로필 및 이력서 상태 관리

### 4.2 Permissions
- `IsOwner`: `obj.member == request.user` 여부 확인

---

## 5. Security & Validation

- **유효성 검증**: 채용 공고 등록 시 필수 항목(제목, 직종, 고용형태) 누락 체크
- **중복 방지**: 한 계정당 구직자 프로필은 1개만 생성 가능하도록 제한
- **XSS 방어**: HTML 내용 입력 시 Django 기본 이스케이프 활용

---

## 6. Implementation Order

1. **Step 1**: `recruit/serializers.py` 작성
2. **Step 2**: `recruit/permissions.py` (IsOwner) 및 서비스 로직(`services.py`) 작성
3. **Step 3**: `recruit/views.py` (ViewSet) 및 `urls.py` 구축
4. **Step 4**: 프리미엄 신청 API 및 포인트 연동 구현
5. **Step 5**: 검색 필터(`filters.py`) 고도화
