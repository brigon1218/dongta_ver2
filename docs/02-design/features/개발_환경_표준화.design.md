# [Design] 개발 환경 표준화 (맥/윈도우 동기화)

## 1. 개요
- **목표**: 맥과 윈도우 11 환경에서 동일한 개발 경험을 제공하기 위한 시스템 설계.
- **핵심 원칙**: "Everything runs on Docker, developed on Unix-based Shell".

## 2. 윈도우 11 환경 표준 (WSL2)
### 2.1 터미널 표준
- **앱**: [Windows Terminal](https://apps.microsoft.com/store/detail/windows-terminal/9N0DX20HK701) (추천)
- **배포판**: Ubuntu 22.04 LTS (WSL2)
- **쉘**: Zsh (macOS와 동일하게 설정 가능)
- **명령어 통일**: `ls`, `grep`, `awk` 등 유닉스 표준 명령어 사용.

### 2.2 Docker 설정
- **엔진**: Docker Desktop for Windows
- **백엔드**: "Use the WSL 2 based engine" 활성화
- **리소스**: "WSL Integration" 설정에서 설치한 Ubuntu 배포판 활성화.

## 3. Django 설정 최적화 (base.py)
### 3.1 경로 처리 로직 개선
- `BASE_DIR`을 기준으로 하는 모든 경로는 `pathlib.Path` 객체를 사용하여 결합.
- 예시: `env.path('SECRET_KEY_PATH', default=BASE_DIR / 'secrets' / 'key.txt')`

### 3.2 환경 변수 우선순위
1. `docker-compose.yml` 내의 `environment` 섹션
2. 로컬 `.env` 파일 (Git 무시 대상)
3. `base.py` 내의 기본값(Default)

## 4. 시크릿 키 및 인증서 관리 설계
- **위치**: 프로젝트 루트 내 `secrets/` 디렉토리 (보안상 `.gitignore`에 추가)
- **Nginx SSL**: 
  - `config/nginx/ssl/www.dongta.com.pem`
  - `config/nginx/ssl/www.dongta.com.key`
  - 이 경로들은 Docker 볼륨 마운트를 통해 컨테이너 내부(`/etc/nginx/ssl/`)로 동일하게 매핑.

## 5. 실행 환경 단일화 설계
- **Makefile** 도입 (맥과 WSL2에서 공통 지원):
  ```makefile
  up:
  	docker-compose up -d
  down:
  	docker-compose down
  shell:
  	docker-compose exec web python manage.py shell
  migrate:
  	docker-compose exec web python manage.py migrate
  ```

## 6. 보안 및 예외 처리
- `.env` 파일에 절대 경로(예: `C:\Users\...`)가 포함되지 않도록 검증 가이드 추가.
- WSL2 내의 `/mnt/c/...` 경로(Windows 파일 시스템) 대신 WSL 전용 파일 시스템(`/home/user/...`) 사용 권장.
