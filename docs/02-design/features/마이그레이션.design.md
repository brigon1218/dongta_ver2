## 1. Overview

### 1.1 Design Goals

1. **무중단 마이그레이션**: 기존 PHP 서비스와 신규 Django API 병행 운영으로 서비스 중단 없음
2. **보안 즉시 개선**: Phase 0에서 SQL Injection, md5 암호화, DB 접속 정보 노출 즉시 해결
3. **현대적 아키텍처**: Django ORM + PostgreSQL로 보안/성능/확장성 확보
4. **점진적 전환**: 모듈별 안전한 전환 검증 후 다음 단계 진행
5. **테스트 기반 개발**: 신규 Django 코드 80% 이상 커버리지 확보

### 1.2 Design Principles

- **Django ORM 우선**: 직접 SQL 작성 최소화 → SQL Injection 구조적 차단
- **12-Factor App**: 환경변수, 로그, 의존성 분리
- **API-First**: 모든 비즈니스 로직은 REST API로 노출 → 프론트 독립성 확보
- **Strangler Fig Pattern**: 레거시를 점진적으로 신규로 교체
- **관심사 분리**: Django apps 단위로 도메인 분리

## 2. Architecture

### 2.1 전체 시스템 아키텍처

#### Phase 0 (즉시 보안 패치 - 기존 PHP 유지)
```
[Client]
    │
    ▼
[Apache + PHP 레거시]
    ├── include/PHP_LIB.inc → .env 파일로 DB 접속 정보 이동
    ├── 핵심 쿼리 → Prepared Statement 교체
    └── MD5 → bcrypt 패스워드 교체
    │
    ▼
[MySQL AWS RDS]
```

#### Phase 1-2 (하이브리드 운영)
```
[Client Browser / Mobile]
    │
    ▼
[Nginx Reverse Proxy - www.dongta.com]
    ├── /api/v1/* ──────────────────────────▶ [Django + DRF]
    │                                              │
    │                                         [PostgreSQL RDS]
    │                                              │
    │                                         [Redis Cache]
    │
    └── /* ────────────────────────────────▶ [Apache + PHP 레거시]
                                                   │
                                              [MySQL RDS]
                                              (동기화 대상)
```

#### Phase 3-4 (완전 전환)
```
[Client Browser / Mobile / App]
    │
    ▼
[Nginx + Gunicorn]
    │
[Django REST Framework API]
    ├── apps/accounts/
    ├── apps/business114/
    ├── apps/recruit/
    ├── apps/board/
    ├── apps/payment/
    └── apps/mypage/
    │
    ▼
[PostgreSQL RDS] ←→ [Redis (Celery + Cache)]
```


### 2.3 데이터 동기화 아키텍처 (하이브리드 기간)

```
[PHP 레거시 서비스]
        │ 데이터 변경 발생
        ▼
[MySQL Binlog / Polling]
        │
        ▼
[Celery Worker (Python)]
        │ 변환 및 정규화
        ▼
[PostgreSQL (Django)]

동기화 방향: MySQL → PostgreSQL (단방향, 레거시가 Master)
동기화 주기: 실시간 (Binlog) 또는 5분 주기 (Polling)
```

### 3.7 MySQL → PostgreSQL 컬럼 매핑 요약

| MySQL (PHP) | PostgreSQL (Django) | 변환 사항 |
|-------------|---------------------|-----------|
| `memb_id` | `username` | 이름 정규화 |
| `memb_encrypt_passwd` (md5) | `password` (bcrypt) | 해싱 알고리즘 교체 |
| `memb_hp1`+`memb_hp2`+`memb_hp3` | `phone` | 3개 컬럼 → 1개 통합 |
| `memb_tel1~4` | `landline` | 4개 컬럼 → 1개 통합 |
| `memb_post1`+`memb_post2` | `postal_code` | 2개 → 1개 통합 |
| `memb_addr1`+`memb_addr2` | `address` | 2개 → 1개 통합 |
| `memb_regdate`+`memb_regtime` | `created_at` (DateTimeField) | 날짜+시간 통합 |
| `memb_jumin1`+`memb_jumin2` | (제거) | 개인정보 보호법 준수 |
| `notice_occupation` (|구분) | `occupations` (JSONField) | 문자열 → JSON 배열 |
| `yellow_item` (1~40+) | `items` (JSONField) | 숫자 열거 → JSON |
| Google_Member, Naver_Member | `google_id`, `naver_id` on Member | 통합 |

## 4. API Specification

### 4.1 공통 규칙

- **Base URL**: `https://www.dongta.com/api/v1/`
- **인증**: JWT (Bearer Token, Access 1h / Refresh 7d)
- **응답 형식**: JSON

**표준 응답 형식**:
```json
{
  "success": true,
  "data": {},
  "error": null,
  "meta": {
    "page": 1,
    "total": 100,
    "limit": 20
  }
}
```

**에러 응답 형식**:
```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "입력값이 올바르지 않습니다.",
    "details": {"username": ["이미 사용 중인 아이디입니다."]}
  }
}
```

```php
// 기존 md5 검증 유지 (마이그레이션 기간) + bcrypt 저장
function verifyAndMigratePassword($inputPass, $storedMd5, $storedBcrypt) {
    if ($storedBcrypt && password_verify($inputPass, $storedBcrypt)) {
        return true; // bcrypt 인증 성공
    }
    if ($storedMd5 && md5($inputPass) === $storedMd5) {
        // md5 인증 성공 → bcrypt로 업그레이드
        $bcryptHash = password_hash($inputPass, PASSWORD_ARGON2ID);
        updateMemberBcryptPassword($membIdx, $bcryptHash);
        return true;
    }
    return false;
}
```

### 8.1 마이그레이션 단계

### 8.2 마이그레이션 스크립트 구조

```python
# data_migration/migrate_members.py
import psycopg2
import pymysql
from passlib.hash import argon2

def migrate_members(mysql_conn, pg_conn):
    """TBL_MEMB → accounts_member"""
    cursor_mysql = mysql_conn.cursor(dictionary=True)
    cursor_pg = pg_conn.cursor()

    cursor_mysql.execute("""
        SELECT memb_idx, memb_id, memb_encrypt_passwd,
               memb_name, memb_email, memb_level,
               CONCAT(memb_hp1, memb_hp2, memb_hp3) as phone,
               memb_region, memb_corp, memb_regdate
        FROM TBL_MEMB
        WHERE memb_wantquitflag = '0'
    """)

    for row in cursor_mysql.fetchall():
        # 전화번호 정규화
        phone = normalize_phone(row['memb_hp1'], row['memb_hp2'], row['memb_hp3'])

        # 패스워드: MD5 보존 + bcrypt placeholder
        # 실제 bcrypt는 첫 로그인 시 자동 업그레이드
        cursor_pg.execute("""
            INSERT INTO accounts_member
            (id, username, password, name, email, level, phone, region,
             corp_name, created_at, is_deleted)
            VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, false)
            ON CONFLICT (id) DO NOTHING
        """, (
            row['memb_idx'],
            row['memb_id'],
            f"md5${row['memb_encrypt_passwd']}",  # 마이그레이션 기간 임시
            row['memb_name'],
            row['memb_email'],
            row['memb_level'],
            phone,
            row['memb_region'],
            row['memb_corp'],
            row['memb_regdate']
        ))

    pg_conn.commit()
    print(f"회원 마이그레이션 완료: {cursor_mysql.rowcount}건")


def verify_migration(mysql_conn, pg_conn):
    """마이그레이션 검증"""
    mysql_count = mysql_conn.cursor().execute("SELECT COUNT(*) FROM TBL_MEMB WHERE memb_wantquitflag='0'")
    pg_count = pg_conn.cursor().execute("SELECT COUNT(*) FROM accounts_member WHERE is_deleted=false")

    assert mysql_count == pg_count, f"카운트 불일치: MySQL={mysql_count}, PG={pg_count}"
    print("마이그레이션 검증 통과")
```

### 8.3 주요 데이터 변환 규칙

| 변환 항목 | 규칙 |
|-----------|------|
| 전화번호 (3컬럼) | `{hp1}{hp2}{hp3}` → `010-1234-5678` 정규화 |
| 주소 (2컬럼) | `addr1 + " " + addr2` 통합 |
| 직종 (파이프 구분) | `"개발\|디자인"` → `["개발", "디자인"]` JSON |
| 날짜+시간 (2컬럼) | `regdate + " " + regtime` → DateTimeField |
| 주민번호 | **저장 안 함** (개인정보 보호법) |
| MD5 패스워드 | `md5$[hash]` 임시 저장 → 로그인 시 bcrypt 업그레이드 |
