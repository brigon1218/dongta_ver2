> **Project**: dongta.com
> **Phase**: Phase 3 (모듈별 완전 전환)

---

## 1. Overview

### 1.1 Purpose

현재 PHP 기반으로 운영 중인 `business114/` 모듈을 Django API 기반으로 완전히 전환하여 업종별/지역별 업체 검색 속도를 높이고 관리 편의성을 향상시킨다.

### 1.2 Background

- **현황**: 업체 데이터는 이미 `sync` 파이프라인을 통해 PostgreSQL로 동기화되고 있음. 기초적인 CRUD 뷰가 이미 작성되어 있음.
- **문제점**: 
  - `items` (JSONField) 필터링 로직이 미비하여 취급 품목별 정밀 검색이 어려움.
  - API 구조가 `recruit` 모듈과 달라 일관성이 부족함.
  - 이미지 업로드 및 권한 관리가 초기 단계임.

---

## 2. Scope

### 2.1 In Scope

- **업체 관리 (CRUD)**:
  - `ModelViewSet` 기반의 일관된 API 구조 리팩토링
  - 본인 등록 업체에 대한 수정/삭제 권한 (`IsOwner`) 적용
  - 신규 업체 등록 시 승인 대기 상태(is_approved=False) 처리
- **고도화된 검색 (Search & Filter)**:
  - `items` (JSONField) 내 특정 품목 ID 포함 여부 검색
  - 지역(address), 업종(industry_type), 업체유형(business_type) 다중 필터
  - 키워드 통합 검색 (업체명, 키워드, 설명)
- **이미지 및 기타**:
  - 업체 로고 이미지 처리 (S3 연동 기반)
  - 조회수(`view_count`) 증가 로직 안정화

### 2.2 Out of Scope

- 지도 API 연동 (추후 프론트엔드 작업 시 고려)
- 업체 간 채팅/문의 기능
- 유료 광고 프리미엄 업체 우선 노출 (채용 정보 모델 참고하여 향후 확장 가능성만 열어둠)

## 3. Requirements

### 3.1 Functional Requirements

| ID | Requirement | Priority | Status |
|----|-------------|----------|--------|
| FR-01 | 업체 정보 등록 및 수정 (ViewSet) | High | Pending |
| FR-02 | 본인 데이터 보호 (IsOwner Permission) | High | Pending |
| FR-03 | 업종/지역/유형별 다중 필터 검색 | High | Pending |
| FR-04 | 취급 품목(JSONField) 검색 기능 | High | Pending |
| FR-05 | 업체 상세 조회 시 조회수 자동 증가 | Medium | Pending |
| FR-06 | 관리자 승인 전후 목록 노출 제어 | High | Pending |

### 3.2 Non-Functional Requirements

- **일관성**: `recruit` 앱과 동일한 디자인 패턴(ViewSet, Serializer, Response Format) 사용.
- **성능**: 복합 필터 검색 시 300ms 이내 응답.
- **보안**: 이미지 업로드 시 파일 확장자 및 크기 제한.

---

## 4. Architecture

### 4.1 핵심 컴포넌트

- **Serializers**: `BusinessSerializer`, `BusinessCreateSerializer`
- **Views**: `BusinessViewSet` (ModelViewSet)
- **Filters**: `occupations__contains`와 유사한 `items__contains` 필터링 적용
- **Permissions**: `core.permissions` 또는 `recruit.permissions`의 `IsOwner` 재사용

---

## 5. Implementation Roadmap

1. **Step 1**: `BusinessViewSet` 리팩토링 및 `DefaultRouter` 적용
2. **Step 2**: `items` (JSONField) 필터링을 포함한 검색 로직 고도화
3. **Step 3**: 본인 데이터 수정 권한 및 상태 제어(`is_approved`) 보완
4. **Step 4**: 이미지 처리 로직 점검 및 Admin 관리 기능 강화
5. **Step 5**: 최종 API 테스트 및 갭 분석

---

## 6. Success Criteria

- 업체 검색 및 필터링이 설계된 모든 조건에 대해 정확히 작동
- 본인이 등록하지 않은 업체 정보를 수정할 수 없음을 검증
- 모든 응답 형식이 `recruit` 모듈과 일관되게 반환됨
- 일치율(Match Rate) 90% 이상 달성
